# TSLink web (car side)

The page that runs in the Tesla browser: Android Auto–style rail + one pane
showing the phone's apps, streamed over WebTransport (see
`../docs/PROTOCOL.md`). Vite + TypeScript, no UI framework.

## Dev

```sh
npm install
npm run dev            # http://localhost:5173/
npm test               # unit tests (incl. the certificate test vector)
npx tsc --noEmit       # typecheck
```

Dev overrides go in the URL **fragment** (never sent to a server; the page
strips it from the address bar and history on load, and doesn't save it):
`http://localhost:5173/#code=ABCD-EFGH-JKLM&host=127.0.0.1&port=24433`

Query flags: `?demo=1` (demo mode, below), `?debug=1` (start with the debug
overlay open; tapping the clock also toggles it), `?codec=h264` (offer only
H.264 to the phone).

The debug overlay is the only diagnostics in the car (no devtools): besides
stream stats it shows the build id, user agent, whether WebTransport and
VideoDecoder exist, the detected codecs, service worker state, UTC time, the
certificate week and fingerprint (compare with the phone; see
`../docs/PROTOCOL.md`), and the last 15 log lines (worker, decode and
connection errors).

If HEVC decoding fails repeatedly (3 errors within 10 s), the page reconnects
offering only H.264 for the rest of the page session ("Switched to H.264").

Settings (code/host/port) are otherwise entered on the pairing screen (gear
icon in the rail) and kept in `localStorage`. A saved code is never shown
again: the field is empty with a masked placeholder (`••••-••••-XY7Q`), and
saving with it empty keeps the saved code. Defaults: `9.9.0.1:4433`. The
same screen has a Display setting (whether notification banners show message
text); it applies and saves on tap, without reconnecting. The phone's UI size
is automatic: the biggest that keeps apps in their wide layout (`paneDpi`).

Rail and launcher: long-press (500 ms, holding still) an app tile, or an app
on the rail, for Open / Pin to rail / Unpin. Up to 5 pinned apps stay at the
top of the rail (`tslink.pins`), above the recents (which skip pinned apps);
a dot under a pinned app means it's running. The launcher has a search field
(label, case and accents ignored) and an A–Z strip of the letters that have
apps; either one shows a flat, sorted list instead of the category groups.
While the phone can't be reached, a help panel (after 2.5 s on a first
connect, at once on an error) says what to check for that error, with
Pairing and Retry now buttons.

## Demo mode

`?demo=1` needs no phone: it plays `public/demo/clip.h264` (Annex B H.264,
1920x1200@60, not in git — copy it from `../spike/clip.h264`) through the
same worker decode path at 60 fps, looping, with a fake app list. Fake
notification banners arrive 3-11 s after start (a call banner stays until
25 s); tapping one shows a toast instead of sending `notif-open`.

```sh
cp ../spike/clip.h264 public/demo/
npm run dev   # open http://localhost:5173/?demo=1
```

## Build

```sh
npm run build          # -> dist/ (typechecks first)
npm run preview        # serve dist/ on http://localhost:4173/
```

`base: './'` makes the build work from any subpath. Production builds
register `sw.js` (generated by `vite.config.ts`), a cache-first service
worker for the app shell, so the page opens offline after the first visit —
important in the car, which may have no internet while on the phone's hotspot.
The demo clip is not precached. Builds also get a strict
Content-Security-Policy `<meta>` (see `vite.config.ts`; build-only because the
dev server injects inline styles).

## Deploy to GitHub Pages

WebTransport, WebCodecs and service workers need a secure context, so the page
must be served over HTTPS (Pages is). Example workflow
(`.github/workflows/pages.yml` in the repo root):

```yaml
on: { push: { branches: [main] } }
permissions: { pages: write, id-token: write, contents: read }
jobs:
  deploy:
    runs-on: ubuntu-latest
    environment: { name: github-pages }
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 22 }
      - run: npm ci && npm test && npm run build
        working-directory: web
      - uses: actions/upload-pages-artifact@v3
        with: { path: web/dist }
      - uses: actions/deploy-pages@v4
```

(Demo mode on Pages needs the clip committed or uploaded separately; it is
gitignored because it's 12 MB. Without it, demo mode says so and still shows
the fake apps and banners.)

## Layout

| file | |
|---|---|
| `src/main.ts` | UI: rail (pins + recents), launcher (search, A–Z), connection help, banners, pairing + display settings, debug overlay, layout messages |
| `src/connection.ts` | WebTransport session, auth handshake, control stream, pings/RTT, reconnect loop |
| `src/auth.ts` | control-stream auth MAC (HMAC-SHA256 over the phone's nonce) |
| `src/reorder.ts` | per-pane frame sequencing: reorder, sync to keyframes, gaps, seq wraparound |
| `src/lines.ts` | JSON-lines splitter for the control stream |
| `src/worker.ts` | WebCodecs decode per pane, newest-frame drawing |
| `src/cert.ts` | deterministic certificate hash from the pairing code (matches `core/src/cert.rs`) |
| `src/touch.ts` | pointer events -> `touch` messages, ripple |
| `src/h26x.ts` | Annex B parsing, codec string from SPS |
| `src/pins.ts` | apps pinned to the rail: storage parsing, pin/unpin, recents without the pinned |
| `src/search.ts` | launcher search: label filter, A–Z letter index |
| `src/longpress.ts` | long press on a tile/rail app (opens the pin sheet), swallowing the lift's click |
| `src/help.ts` | connection help panel: error status -> what to check |
| `src/notifs.ts` | notification banners: validation/truncation of `notif`, banner queue and expiry |
| `src/diag.ts` | pure helpers: code masking, cert fingerprint, HEVC error window, debug log ring |
| `src/demo.ts` | demo feeder + fake apps + fake notifications |
| `src/protocol.ts` | message types, 24-byte frame header |
